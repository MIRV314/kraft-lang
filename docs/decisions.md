# Решения по языку и реализации

Этот файл — источник истины для компилятора. README объясняет язык
программисту; здесь — что именно считается правильным. Если README и этот
файл расходятся, прав этот файл (и README надо поправить).

## Язык

**D1. Статическая типизация.** Тип переменной задаётся объявлением и не
меняется. `flint` — один числовой тип (внутри double): целые и дробные не
различаются. Неявных приведений нет: `flint x = "5"` — `TYPE_ERROR`.

**D2. `NONE` — обычное значение.** Его можно писать в коде и присваивать
переменной любого типа. Это не «сломанный тип», а пустое значение.

**D3. Операции с `NONE` падают в рантайме.** `NONE + 1` →
`TYPE_MISMATCH_ERROR`. Переприсвоил число — переменная снова нормальная.
Исключения: `==`, `!=`, `is NONE`, `show`, присваивание, `return:`.

**D4. Полная статика, кроме чтения из коллекции без параметра типа.**
`list`/`dict` без параметра могут хранить разные типы; чтение из них
проверяется в рантайме. `list[flint]`/`dict[str|flint]` закрывают дырку.
Никакого типа `any` в языке нет — только внутренняя пометка компилятора.

## Функции и возврат

**D5. `-> тип` опционален.**
- есть аннотация — это контракт, каждый `return` проверяется;
- нет аннотации — тип выводится: все `return expr` должны давать один тип;
- `return:` (пустой) совместим с любым типом, но помечает «может быть NONE»;
- нет `return` вообще — функция типа `NONE`.

**D6. Разные типы в `return` без аннотации — ошибка компиляции**, а не
«неизвестный тип».

**D7. Рекурсия без `->` — ошибка:** тип из себя самого не выводится.

**D8. `-> NONE` не пишется.** Пустой возврат — это отсутствие `->`.

**D9. Аннотации возврата:** `-> flint`, `-> str`, `-> bool`, `-> list`,
`-> list[flint]`, `-> dict`, `-> dict[str|flint]`.

**D10. `--types` — не в v0.1.** Отладочный вывод сигнатур отложен.

## Область видимости

**D11. Область — функция.** Объявление видно с точки объявления до конца
функции, даже если оно внутри `if`/`while`. Если блок не выполнялся —
значение `NONE`.

**D12. Повторное объявление в одной функции — `REDECLARE_ERROR`.**

**D13. Объявляй до `if`.** Два объявления одного имени в `if` и `else` —
ошибка. Это цена простой модели области.

**D14. Переменная `for` — только цикл.** Она не видна после цикла, не
перекрывает внешнее имя и не может быть объявлена второй раз в той же
функции. `for i` дважды — `REDECLARE_ERROR`.

**D15. `for I 5:`** — имя капсом означает константу, цикл её присваивает →
`CONST_ERROR`. Отдельного правила не нужно.

**D16. `break`/`continue` — только в цикле, `return` — только в функции.**

## Операторы

**D17. Арифметика как в Python.** `/` — истинное деление (`7 / 2` → `3.5`);
`//` — floor (`-7 // 2` → `-4`); `%` — знак делителя (`-7 % 3` → `2`);
`**` — вправо (`2 ** 3 ** 2` → `512`); `*` — умножение.

**D18. Деление на 0 → `VALUE_ERROR`.** Отрицательная степень с дробным
показателем → `VALUE_ERROR`.

**D19. `+` со строкой → `CONCATENATE_NOT_SUPPORT` при компиляции.**

**D20. Сравнения.** `==`/`!=` — любые типы: разные типы дают `FALSE`,
`NONE == NONE` — `TRUE`. `< <= > >=` — только `flint`-`flint` и
`str`-`str` (побайтово), иначе ошибка.

**D21. Цепочки сравнений** (`0 <= x <= 10`) раскрываются в `AND`; средний
операнд вычисляется **один раз** (временная переменная).

**D22. `AND`/`OR` ленивые, результат `bool`, операнды проверяются на
истинность.** `NOT` даёт `bool`.

**D23. Истинность:** ложь только `NONE` и `FALSE`; `0`, `""`, `[]`, `{}` —
истинны.

## Строки и интерполяция

**D24. `{}` — единственная интерполяция.** `$` — обычный символ.
Работает и в строковых литералах, и в шаблонах `show`/`show_err`/`input`.

**D25. Правила `{}`:**
- `{выражение}` — подстановка; внутри обычное выражение;
- всё вне `{}` — текст: `show({x} + 1)` → `5 + 1`;
- `\{` и `\}` — литеральные скобки; `}` вне подстановки — ошибка;
- пустая подстановка `{}` — `SYNTAX_ERROR`;
- вложенные `{}` внутри выражения — литерал словаря: `show({ {a: 1} })`.

**D26. В шаблонах `show(...)` скобки `(` и `)` — синтаксис вызова**, поэтому
в тексте шаблона они экранируются: `show(a \(b\))` → `a (b)`.

**D27. Escape-последовательности:** `\\ \" \' \n \t \r \e \{ \}`. Внутри
`"..."` экранируется двойная кавычка, внутри `'...'` — одинарная; «чужая»
кавычка не экранируется.

**D28. Печать значений:** `str` на верхнем уровне без кавычек, внутри
коллекций — в кавычках; целое без `.0`, иначе до 14 значащих цифр;
`TRUE`/`FALSE`; `NONE`; `[a, b]`; `{k: v}`.

**D29. `show`/`show_err` возвращают `NONE`, `input` — `str`.**

## Коллекции

**D30. `s[i]` — строка из одного символа.** Индексы в символах UTF-8.
Отрицательный индекс — с конца. За границей → `VALUE_ERROR`.

**D31. Срезы:** правая граница не входит, открытые границы, отрицательные,
шаг. Обратный диапазон → пусто. Шаг `0` в срезе → `VALUE_ERROR`; шаг `0`
в `for` → пустой цикл.

**D32. Ключ словаря в `[]`** — только bare-имя или строковый литерал.
Переменная-ключ — через `take(k)`. Иначе `TYPE_ERROR`.

**D33. `list[T]`/`dict[K|V]`:** содержимое литерала проверяется при
компиляции; `add`/`set`/`insert` — при компиляции, если аргумент известен
статически, иначе в рантайме.

## Ошибки

**D34. `TYPE_ERROR` — компиляция, `TYPE_MISMATCH_ERROR` — рантайм.**

**D35. Ошибки с кареткой и `expected/found`.** Рантайм-ошибки тоже с
кареткой: строки исходника и карта «строка Lua → строка Kraft» вшиваются
в сгенерированный Lua. Позиция берётся по стеку и указывает на начало
выражения, в котором возникла ошибка.

**D36. Цвета только на TTY stderr.** Столбцы — в символах UTF-8.

## CLI и рантайм

**D37. Пользовательский CLI:** `./kraft file.kraft [args...]` — запуск.
`./kraft -c file.kraft` — собрать самодостаточный `.lua` рядом с исходником
(без запуска). Скрытый флаг для разработки: `--emit-lua` — печать Lua.

**D38. Сгенерированный `.lua` самодостаточен:** `krt` вшит, шебанг
`#!/usr/bin/env luajit`, строки исходника вшиты — рантайм-ошибки работают
и без исходного файла.

**D39. `args()[0]` — путь к `.kraft`-исходнику**, дальше аргументы
программы.

**D40. `NONE` в рантайме — sentinel `krt.NONE`, не `nil`.**

**D41. `dict` сохраняет порядок вставки:** `{keys = {...}, vals = {...}}`.

**D42. Манглинг имён:** переменные `v_N` по порядку объявления, функции
`f_N` по порядку объявления. Кириллица в переменных разрешена.

**D43. `continue` → `goto` (LuaJIT 2.1).** Локали поднимаются в начало
функции, переменная `for` — свой `local` внутри цикла.

**D44. `is_tty()` — FFI `isatty(2)`**, единственное LuaJIT-специфичное
место.

**D45. `time_ms()` — `os.clock() * 1000`** (процессорное время).

## Ядро и std

**D46. Ядро:** `show`, `show_err`, `input`, `type`, `str`, `flint`, `len`,
`read_file`, `write_file`, `file_exists`, `args`, `exit`, `time_ms`,
`is_tty`, `up`, `low`, `title`, методы типов.

**D47. Std на Kraft (v0.2, через импорты):** `min`, `max`, `sum`, `avg`,
`upk`, `sort`, `reverse`, `clear`, `map`, `filter`, `reduce`, `assert`,
`expect`.

**D48. `system` — v0.2**, для std и xkraft не нужен: запуск делает
обёртка `kraft`.

**D49. Импорты (`import_file`/`from_file`) — v0.2, до std.**

## Константы

**D50. Константа — имя без строчных латинских букв** (`MAX`, `MAX_SIZE`,
`X`). Присваивание → `CONST_ERROR`.

## Функции

**D51. Функция видна после объявления.** Вызов до объявления — `NAME_ERROR`.
Своё имя функция видит с начала тела: рекурсия работает. Если `->` нет,
вызывать себя нельзя — `TYPE_ERROR` («нужен явный `->`»), потому что тип
возврата ещё не выведен.

**D52. Тело функции — отдельная область.** Видны только параметры и
локальные; переменные файла — нет (`NAME_ERROR`). Функции верхнего уровня
вызывать можно. Объявления внутри тела поднимаются в начало **этой**
функции, не программы.

**D53. Возможный «провал» тела.** Если тело не заканчивается `return`,
функция может вернуть `NONE`; её результат помечается «может быть NONE», и
операции над ним проверяются в рантайме. Это же верно для `return:` и
`return NONE` при явном `->`.

## Строки: индексы, срезы, методы

**D54. `s[i]` и срезы — в символах UTF-8.** Индексация с 0, отрицательный
индекс — с конца, за границей — `VALUE_ERROR`. Срез `s[a..b]`: правая
граница не входит, границы могут быть открыты (`s[..b]`, `s[a..]`),
отрицательные индексы нормализуются, границы зажимаются в диапазон.
Шаг `0` — `VALUE_ERROR`; положительный шаг при `a > b` и отрицательный при
`a < b` дают пустую строку. `s[3..1..-1]` — обратный порядок. Шаг должен
быть целым (`VALUE_ERROR`), иначе индексы становятся дробными.

**D55. Методы строк** (0-based, индексы в символах):
`part(a, b?)` — подстрока `a..b` (без `b` — до конца);
`find(sub)` — индекс первого вхождения или `NONE`;
`contains(sub)` — `bool`;
`preff(p)` / `suff(p)` — начинается/заканчивается на `p`;
`trim()` / `triml()` / `trimr()` — убрать пробелы;
`replace(old, new)` — заменить все вхождения;
`count(sub)` — число неперекрывающихся вхождений (`""` → `0`).
`find` помечен «может быть NONE»; пустая подстрока в `replace` ничего не
меняет.

## Коллекции без параметра типа

**D56. `list` и `dict` без параметра — динамические.** Они хранят значения
любых типов. Чтение (`xs[i]`, `d[k]`, `take`) имеет внутренний тип `any`:
он совместим с любым типом при объявлении, присваивании, передаче в
функцию и `return`, а операция, которой нужен конкретный тип, проверяется
в рантайме (`TYPE_MISMATCH_ERROR`). Индекс, срез и `for-in` по `any`
выбирают тип в рантайме: `for x in v` — список, `for k, v in v` — словарь.
Метод у `any` не вызывается: сначала привяжи значение к типу
(`list row = xs[0]`), потом вызывай `row.add(...)`. `is` смотрит на
фактический тип значения. `list[flint]` / `dict[str|flint]` — после v0.1.

**D57. Литералы.** `[a, b, c]` — список, `{}` — пустой словарь,
`{ключ: значение}` — словарь. Ключ — bare-имя или строковый литерал без
интерполяции; `user[имя]` и `user["имя"]` — один ключ `"имя"`. Порядок пар
сохраняется. Повторный ключ заменяет значение и не меняет позицию.

**D58. Индексы и срезы списка** — как у строк (D54): с 0, отрицательные с
конца, за границей — `VALUE_ERROR`. Срез возвращает новый список; шаг `0` —
`VALUE_ERROR`; шаг должен быть целым (D54); пустой диапазон — пустой
список.

**D59. Чтение словаря.** `d[ключ]` и `d.take(ключ)` возвращают значение или
`NONE`, если ключа нет (не ошибка). Ключ всегда `str`; динамический ключ
(переменная, выражение) передаётся только в методы. Методы: `add(k, v)`,
`take(k)`, `remove(k)` → `bool`, `contains(k)` → `bool`,
`merge(other)` — пары `other` перезаписывают совпавшие ключи.

**D60. Методы списка.** `add(v)` — в конец; `del(i)` — по индексу
(`VALUE_ERROR` за границей); `remove(v)` → `bool`, удаляет первое
вхождение; `replace(i, v)`; `contains(v)` / `count(v)`; `index(v)` — индекс
или `NONE`; `join(sep)` — элементы через `str`, разделитель `str`.

**D61. `for ... in`.** По списку — одна переменная (элементы), по словарю —
две (ключ, значение) в порядке вставки. Коллекция вычисляется один раз.
Имена переменных подчиняются D14: `for x` дважды в одной функции —
`REDECLARE_ERROR`.

**D62. Коллекции — по ссылке.** Присваивание, передача в функцию и `for-in`
не копируют список/словарь: изменение через одну переменную видно через
другую. `==`/`!=` сравнивают ссылки (одна и та же коллекция — `TRUE`).

## Встроенные функции

**D63. Преобразования.** `len(x)` — `str` (символы UTF-8), `list`
(элементы) или `dict` (ключи). `type(x)` — имя типа текстом. `str(x)` —
печать значения как на верхнем уровне. `flint(x)`: число как есть,
`bool` → 1/0, `str` → разбор (`"abc"` → `VALUE_ERROR`), остальное —
`TYPE_MISMATCH_ERROR`.

**D64. Файлы.** `read_file(path)` возвращает весь файл как `str`; нет
файла — `FILE_ERROR`. `write_file(path, text)` перезаписывает файл целиком
и возвращает `bool`; ошибка записи — `FILE_ERROR`. `file_exists(path)` →
`bool`.

**D65. Процесс.** `args()` → `list[str]`, `[0]` — путь к исходнику (D39).
`exit(code)` завершает программу. `time_ms()` — `os.clock() * 1000`.
`is_tty()` — `isatty(2)` (D44). Имена встроенных функций зарезервированы:
объявление переменной, функции, параметра или переменной цикла с таким
именем — `NAME_ERROR`.

## Ввод для тестов

**D66. `# stdin: текст`.** Строка-комментарий с этим префиксом (отступ
разрешён) задаёт строку встроенного ввода. `input()` читает такие строки
по порядку, затем настоящий stdin. Пробелы после `:` — разделитель, пустой
хвост — пустая строка. Строки вшиваются в сгенерированный Lua, поэтому
работают и в `-c`.
