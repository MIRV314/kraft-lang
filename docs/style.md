# Стиль кода Kraft

- Отступ — 4 пробела. Табуляция и пробелы внутри одного блока не смешиваются.
- Один оператор на строку, `;` не нужен.
- Имена — `snake_case`; константы — `UPPER_CASE`; модели — `CapWords`.
- Тип при объявлении указывается всегда. `-> type` добавляется, когда результат
  нужно зафиксировать: рекурсия, публичный API или неочевидный вывод.
- Параметры `[]` указываются только для конкретных задач. Обычные `list`,
  `dict`, `froz` остаются без параметров.
- Строки: двойные кавычки; интерполяция — в `show`/`show_err`/`input`. Для
  категорий ошибок, ключей dict и аргументов `panic` используются plain-строки
  без подстановок.
- Комментарии пишутся по-русски в компиляторе и тестах; сообщения об ошибках —
  по-английски, в формате `expected X, found Y`.
- `dev/xkraft.kraft` обязан собираться замороженным v0.1: без новых конструкций
  языка, `|` в выражениях, `froz`, `panic`, `try` и моделей. Спецификации типов
  передаются строками вида `"dict[str, flint]"`.
- В модулях нет `export`: все объявления верхнего уровня импортируемы, `_`
  не делает имя приватным.
- У методов с необязательным аргументом полная форма первична:
  `part(sep, maxsplit)`, `remove(v, count)`. В документации аргумент
  помечается `?`, в коде пишется без скобок.
- Один тест в `dev/tests/new/` — на одно правило. Успех — `<name>.out`,
  ожидаемый код возврата 1 — дополнительно `<name>.code`.
- Lua прямого и самособранного `xkraft` должны совпадать побайтово.

Базовую проверку этих правил выполняет `dev/tests/style.sh`: табуляция,
отступы, имена, трейлинг-пробелы, `export` и удалённые builtins. Она не входит
в `make check` и не попадает в дистрибутив; ожидаемые данные тестов (`*.out`,
`*.stdin`) и намеренно плохие фикстуры `err_*` пропускаются. Публичная команда
`xkraft lint` доступна в `0.8`.
