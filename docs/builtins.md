# Встроенные функции ядра

Канонический список того, что доступно в любом `.kraft`-файле без
подключения библиотек. Всё это — часть ядра компилятора и рантайма.
Необязательные надстройки (пути, даты, CLI, тест-раннер) в этот список не
входят.

`NONE` можно передать в любой аргумент; проверка типа произойдёт при
использовании. Ошибки типов — `TYPE_ERROR` при компиляции там, где тип
известен, иначе `TYPE_MISMATCH_ERROR` в рантайме.

Граница ядро/std зафиксирована в D119 и уточнена в D120: всё перечисленное
ниже — ядро; std-модули — `std/fos`, `std/cli` и `std/math`.
Prelude подключается автоматически; `--no-prelude` отключает его.

## Глобальные функции

| Группа | Вызовы |
| --- | --- |
| Проверки и размер | `len(x)`, `type(x)`, `str(x)`, `flint(x)` |
| Строки | `up(s)`, `low(s)`, `title(s)` |
| Числа | `abs(n)`, `round(n)`, `floor(n)`, `ceil(n)`, `sqrt(n)`, `factorial(n)`, `fib(n)`, `min(...)`, `max(...)` |
| Коллекции | `sum(xs)`, `avg(xs)`, `keys(d)`, `values(d)`, `upk(coll)`, `sort(xs)`, `reverse(xs)`, `clear(coll)` |
| Функции высшего порядка | `map(xs, f)`, `filter(xs, f)`, `reduce(xs, f, start)` |
| Файлы | `read_file(path)`, `write_file(path, text)`, `file_exists(path)` |
| Процесс | `args()`, `exit(code)`, `time_ms()`, `is_tty()`, `system(command)`, `timer(ms, value)` |
| Тесты | `assert(condition, message)`, `expect(value)` |
| Печать и ввод | `show(template)`, `show_err(template)`, `input(prompt)` |
| Константа | `PI` |

### Проверки и преобразования

- `len(x)` — `str`: символы UTF-8; `list`: элементы; `dict`: ключи.
  Другое — `TYPE_MISMATCH_ERROR`.
- `type(x)` — имя типа текстом: `"str"`, `"flint"`, `"bool"`, `"list"`,
  `"froz"`, `"dict"`, `"range"`, `"func"`, `"NONE"` и имена моделей.
- `str(x)` — текст значения, как при печати.
- `flint(x)` — число как есть, `bool` → `1`/`0`, `str` → разбор;
  неразобранная строка и несовместимый тип — `TYPE_MISMATCH_ERROR`.
- Строка извне (`input()`, `args()`, `read_text()`, ячейка `read_csv()`) может
  присваиваться `flint` без вызова: компилятор вставляет то же преобразование.
  Числовой строковый литерал (`flint n = "42"`) принимается на компиляции,
  нечисловой (`flint n = "x"`) — `TYPE_ERROR`. `list()` и `dict()` как
  приведения не существуют.

### Строки

- `up(s)` / `low(s)` — верхний/нижний регистр латиницы и Latin-1;
  кириллица не меняется.
- `title(s)` — каждое слово с заглавной буквы, остальные строчные.

### Числа

- `PI` — встроенная константа `flint`, число π (`3.1415926535898` при печати).
  Пишется без вызова: `show({PI})`. Математические надстройки лежат в
  `std/math` (D120).
- `abs(n)` — модуль.
- `round(n)` — округление к ближайшему, половина — от нуля:
  `2.5 → 3`, `-2.5 → -3`.
- `floor(n)` / `ceil(n)` — вниз / вверх.
- `sqrt(n)` — корень; отрицательное число — `VALUE_ERROR`.
- `factorial(n)` — произведение `1..n`; `n <= 1` даёт `1`.
- `fib(n)` — числа Фибоначчи: `fib(0) = 0`, `fib(1) = 1`; для `n <= 1`
  возвращается `n`.
- `min(...)` / `max(...)` — от 1 до 9 аргументов. Один аргумент-список —
  минимум/максимум его элементов; иначе все аргументы должны быть
  `flint`. Пустой список — `VALUE_ERROR`.

### Коллекции

- `sum(xs)` — сумма чисел, пустой список → `0`; элементы проверяются.
- `avg(xs)` — среднее; пустой список — `VALUE_ERROR`.
- `keys(d)` → новый список ключей; `values(d)` → новый список значений.
  Например, для `{name: "Kraft"}` это `["name"]` и `["Kraft"]`. Это не
  распаковка: исходный словарь не меняется.
- `upk(coll)` — содержимое без внешних скобок: `[1, "два"]` → `1, "два"`,
  словарь → `имя: "Kraft"`. Разделитель — `", "`. По D113 планируется убрать
  запятые и использовать пробел; до реализации описан текущий вывод.
- `sort(xs)` → **новый** список по возрастанию; только числа. Исходный не
  меняется.
- `reverse(xs)` → **новый** список в обратном порядке.
- `clear(coll)` — очищает список или словарь **на месте**, возвращает
  `NONE`.

### Функции высшего порядка

Функция передаётся **по имени**, лямбд нет: `map(xs, double)`. Если лямбды
когда-нибудь появятся, ключевое слово будет `fn`, не `lambda` (D115).

- `map(xs, f)` → новый список результатов `f(x)`.
- `filter(xs, f)` → новый список элементов, для которых `f(x)` истинно.
- `reduce(xs, f, start)` → свёртка: `f(аккумулятор, x)`.
- `f` должна быть объявлена выше и иметь нужную арность: 1 для
  `map`/`filter`, 2 для `reduce`. Неверная арность — `ARGCOUNT_ERROR`.

### Файлы и процесс

- `read_file(path)` — весь файл; нет файла — `FILE_ERROR`.
- `write_file(path, text)` — перезапись целиком, `bool`; ошибка —
  `FILE_ERROR`.
- `file_exists(path)` → `bool`.
- `args()` → `list[str]`: `[0]` — путь к исходнику, дальше аргументы.
- `exit(code)` — завершить программу.
- `time_ms()` — процессорное время в миллисекундах.
- `is_tty()` — `TRUE`, если stderr — терминал.
- `system(command)` — запуск через `/bin/sh -c`; код выхода `0..255`,
  по сигналу — `128 + номер`, не запустилось — `-1`. Встроенный, доступен без
  импорта; `cli.run(command)` из `std/cli` — тонкая обёртка над тем же
  механизмом.
- `timer(ms, value)` — тестовая приостанавливаемая операция из D106: уступает
  управление event loop на `ms` миллисекунд реального времени и возвращает
  `value`. Вызов стартует внутри программы (она целиком идёт в event loop),
  в `async`-функции приостанавливает именно её; параллельные вызовы ждутся
  одновременно. Ошибки таймера нет; `ms < 0` считается нулём. Ввод, файлы и
  `system()` остаются блокирующими.

### Тесты

- `assert(condition, message)` — если условие ложно, `ASSERT_ERROR` с
  текстом `message`.
- `expect(value)` → значение внутреннего типа `expect` с методами:
  - `.equals(x)` — равно;
  - `.is_true()` / `.is_false()`;
  - `.is_none()`;
  - `.contains(x)` — для строки, списка или словаря.
  При провале — `EXPECT_ERROR`; при успехе — `NONE`.

## Prelude (доступен без import)

Prelude — не часть замороженного ядра v0.1, но он добавляется к каждой
программе `xkraft` по умолчанию. Флаг `--no-prelude` отключает его.

| Вызов | Что делает |
| --- | --- |
| `prelude_cat(xs)` | склеить список строк без разделителя |
| `path_join(a, b)` | соединить части пути через `/`, не удваивая косую |
| `now_ms()` | то же, что `time_ms()` |
| `parse_args()` | разобрать `args()[1..]`: `--k=v` → ключ `k`, `--k` → `"TRUE"`, позиционные → ключи `"1"`, `"2"`, … |
| `parse_csv(data)` | строки по `\n`, пустые пропускаются, поля по `,` |
| `parse_json(data)` | компактный разбор объекта: строковые, числовые и `true`/`false`/`null` значения; не объект → `TYPE_ERROR`, ошибка разбора → `VALUE_ERROR` |

Имена prelude-функций зарезервированы так же, как встроенные (D79).

## Зарезервированное, но не публичное

Эти имена заняты компилятором: их нельзя использовать для своих переменных,
функций и моделей. Обычным программам они не нужны — их вызывает `std/fos`
или сам компилятор.

| Имя | Что делает | Почему не в публичном API |
| --- | --- | --- |
| `copy_file(src, dst)` | копировать файл | есть `fos.copy` |
| `remove_file(path)` | удалить файл | есть `fos.remove` |
| `json_parse(text)`, `json_stringify(value)` | разбор и запись JSON | есть `fos.read_json` / `fos.write_json` |
| `raise(category, message)` | бросить ошибку напрямую | есть `panic` и `try`/`trigger`/`finally` |

Ключевое слово `glob` тоже зарезервировано, но в `xkraft` не используется:
глобальные переменные меняются сразу внутри `func`, `for` и `while`, без
`glob`. В v0.1 оно существовало для изоляции функций и осталось в истории языка.

## Стандартная библиотека

Четыре модуля входят в рабочую поставку `0.9.3` и подключаются через
`import_lib` / `from_lib`:

| Модуль | Имена |
| --- | --- |
| `std/fos` | `exists`, `copy`, `remove`, `read_text`, `write_text`, `read_json`, `write_json`, `read_csv`, `write_csv`, `csv_field`, `csv_line`, `csv_parse` |
| `std/cli` | `run`, `kill` |
| `std/math` | `pow`, `random` |
| `std/base` | `tern`, строковые helper'ы, `render`, паттерны поверх `dict` |

`std/base` (D110, D123) реализован досрочно и входит в `0.9.2` и `1.0`: `tern`,
строковые helper'ы, `render` и ООП-паттерны поверх `model`/`dict`/`self`.
В `1.1` появится `std/http`, сразу async-aware (D104). В опубликованной поставке
`0.9.1` пока только первые три модуля.

- `fos.exists(path)`, `fos.copy(src, dst)`, `fos.remove(path)` → `bool`.
- `fos.read_text(path)` → `str`; `fos.write_text(path, data)` → `bool`.
- `fos.read_json(path)` → `dict`; `fos.write_json(path, value)` → `bool`.
- `fos.read_csv(path)` → список строк; `fos.write_csv(path, rows)` → `bool`.
  Поля разделяются `,`, кавычки внутри поля удваиваются. `csv_parse(data)`
  разбирает строку; `csv_field` и `csv_line` — обычные имена верхнего уровня.
- `cli.run(command)` → код выхода (`-1`, если запустить не удалось); по
  действию совпадает со встроенным `system`, но импортируется из `std/cli`.
  `cli.kill(message)` бросает `VALUE_ERROR`.
- `math.pow(a, b)` — то же, что оператор `**`.
- `math.random(x)` — если `x` — `range`, возвращает случайное значение на его
  сетке; если `x` — список, возвращает случайный элемент. Подробности — в
  [docs/libs.md](libs.md).
- `base.tern(cond, a, b)` — жадный тернарный helper; `base.upper`, `base.lower`,
  `base.capwords`, `base.starts`, `base.ends`, `base.has_text`, `base.find_pos`,
  `base.split`, `base.join_parts`, `base.trim`, `base.replace`,
  `base.count_text` — строковые helper'ы; `base.render(value)` печатает dict,
  list и скаляры; `base.make`, `base.mixin`, `base.get_field`, `base.put_field`,
  `base.has_field`, `base.unset_field`, `base.has_protocol` — паттерны поверх
  `dict`. Полный список — в [docs/libs.md](libs.md).

`json_parse`, `json_stringify`, `rand_num` и `rand_choice` остаются внутренними
встроенными функциями и не импортируются: `std/math` вызывает их сам. `std/fs`,
`std/json`, `std/file`, а также `clamp`, `lerp` и `is_even` в поставку не входят.

## Методы строки

| Метод | Что делает |
| --- | --- |
| `s.part()` | split по пробелам, пустые куски отбрасываются |
| `s.part(sep)` | split по разделителю; пустой `sep` — `VALUE_ERROR` |
| `s.part(sep, maxsplit)` | не больше `maxsplit` разрезов; `maxsplit < 0` — без ограничения |
| `s.find(sub)` | индекс первого вхождения или `NONE` |
| `s.contains(sub)` | `TRUE`, если подстрока есть |
| `s.preff(p)` / `s.suff(p)` | начинается / заканчивается на `p` |
| `s.trim(chars?)` | убрать символы с обеих сторон; по умолчанию пробельные |
| `s.triml(chars?)` / `s.trimr(chars?)` | только слева / только справа |
| `s.replace(old, new)` | заменить все вхождения; `old == ""` → без изменений |
| `s.remove(sub, count?)` | удалить вхождения: без `count` — все, `count` — не больше |
| `s.count(sub)` | число неперекрывающихся вхождений |

Полная форма с необязательным аргументом первична: `s.part(sep, maxsplit)`,
`s.remove(sub, count)`. Знак `?` в таблице означает, что аргумент можно опустить:
`s.part(",")`, `s.remove("x")` — правильный код; `?` в код не пишется.

Подстрока — только срезом: `s[2..7]`, `s[..5]`, `s[7..]`, `s[...2]`,
`s[1...]`. Индексы и длины — в символах UTF-8, с нуля.

## Методы списка

| Метод | Что делает |
| --- | --- |
| `xs.add(v)` | добавить в конец |
| `xs.add(i, v)` | вставить перед индексом `i` |
| `xs.del()` | удалить последний элемент |
| `xs.del(i)` | удалить по индексу |
| `xs.remove(v)` | удалить все вхождения, `bool` |
| `xs.remove(v, count)` | удалить не больше `count` вхождений, `bool` |
| `xs.replace(i, v)` | заменить элемент по индексу |
| `xs.replace_value(a, b)` | заменить первое вхождение значения `a` на `b`, `bool` |
| `xs.contains(v)` / `xs.count(v)` | есть ли / сколько раз |
| `xs.index(v)` | индекс первого вхождения или `NONE` |
| `xs.join(sep)` | элементы через `str`, разделитель `str` |

Полная форма `xs.remove(v, count)` первична; `xs.remove(v)` — краткая запись
без `count`.

`replace(i, v)` остаётся заменой по индексу: на ней держится bootstrap
`xkraft`. Замена значения — `replace_value(a, b)`.

## Методы словаря

| Метод | Что делает |
| --- | --- |
| `d.add(k, v)` | добавить или заменить пару |
| `d.take(k)` | значение или `NONE` |
| `d.remove(k)` | удалить ключ, `bool` |
| `d.contains(k)` | есть ли ключ |
| `d.merge(other)` | **новый** словарь: пары `d`, затем `other` поверх |

Ключ — `str` или `flint`. В `[]` он пишется bare-именем или строковым
литералом: `d[имя]` ≡ `d["имя"]`. `bool`, `NONE`, коллекции и модели ключами
не являются. Динамический ключ — `d.take(k)` и `d.add(k, v)`.

## Индексы и присваивание

```kraft
xs[0]          # чтение
xs[-1]         # с конца
xs[1..5..2]    # срез, правая граница не входит
xs[2...3]      # от 2 до конца, шаг 3
xs[0] = 99     # запись
d[ключ] = 1    # запись по литеральному ключу
```

В срезах `..` разделяет границы, `...` задаёт шаг. Это единый стиль с
`for i a..b..step`. Соответствие с Python: `..` ↔ `:`, `...` ↔ `::`.
Для `xs = [10, 20, 30, 40, 50]`:

| Запись | Что даёт |
| --- | --- |
| `xs[..2]`, `xs[1..4]` | до индекса 2 / от 1 до 4; правая граница не входит |
| `xs[2..]`, `xs[..]` | от 2 до конца / копия всего |
| `xs[2...3]`, `xs[2...]` | от 2 до конца с шагом 3 / с шагом 1 |
| `xs[...2]`, `xs[...]` | весь список с шагом 2 / копия всего |
| `xs[1..4..2]`, `xs[4...-2]` | шаг вправо / шаг влево |

- Индекс списка — `flint`; отрицательный отсчитывается с конца.
- За границей — `VALUE_ERROR`; шаг среза `0` — `VALUE_ERROR`.
- В циклах `...`-форм нет: у `for` нет неявной правой границы.
- Строка неизменяема: `s[0] = "x"` — `TYPE_ERROR`.
- Для `any` (чтение из нетипизированной коллекции) проверка в рантайме.

`pass` — пустой оператор, включён в D118; в срезах и выражениях не участвует.
